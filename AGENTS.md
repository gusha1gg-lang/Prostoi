### [2026-06-20] — Получена детальная спецификация отчёта по простоям

**Контекст:** Заказчик предоставил детальное описание того, как должен выглядеть и работать отчёт по простоям на портале.

**Что сделано:**
- Обновлён `README.md` с полной спецификацией отчёта
- Зафиксированы все детали: фиксированная служба ДИТ, фильтры, справочник цехов, структура таблиц, режимы группировки

**Файлы затронуты:**
- `README.md` — добавлена секция «Детальная спецификация отчёта»

**Ключевые решения из спецификации:**

1. **Служба ДИТ — фиксированная.** Отчёт всегда строится только по ней. Отображается как информационная плашка в шапке. Менять через интерфейс нельзя.

2. **Фильтры:** Дата от/до (обязательно), Цех (из справочника), Участок (из данных), Статус (Новый / В работе / Решён / Вне зоны ОМК-ИТ). Кнопки: Применить, Сбросить, Экспорт в Excel.

3. **Справочник цехов:** В источнике полное название (АО "ВМЗ" - ТЭСЦ-1), в фильтре — короткое (ТЭСЦ-1). В базе хранится полное. Реальные цеха зафиксированы.

4. **Таблица сводных простоев:** ID, Название (редактируемое), Дата, Цех, Участок, Кол-во записей, Общая длительность, Статус, Действия (Открыть/Удалить). Все колонки сортируемые.

5. **Детализация:** Исходные строки с колонками: номер, начало, конец, длительность, причина, примечание, агрегат, участок, ответственный, цех. Редактирование и удаление с пересчётом длительности.

6. **Разбор инцидента:** Шапка + таблица простоев + инцидент + причины (3 вида) + меры + таблица мероприятий + особое мнение + хронология. Экспорт в .docx (Times New Roman, таблицы, жирные заголовки).

7. **Группировка:** Два режима — по цехам за период (ключ: цех + название) и все в один простой.

8. **Абстракция источника:** DataSource с методами getDowntimeRecords, getShops, testConnection. MockDataSource для этапа 1, SAARCDataSource для этапа 2.

**Следующие шаги:**
1. Начать реализацию: структура папок, типы, абстракция DataSource
2. Сгенерировать мок-данные с реальными названиями цехов
3. Создать layout с плашкой ДИТ в шапке
4. Реализовать страницу отчёта с фильтрами и таблицей

## Известные проблемы и ограничения

- Пока нет бэкенда — на этапе 1 всё работает на клиенте с мок-данными
- SQLite на этапе 1 будет через sql.js (WASM) или better-sqlite3 на сервере
- Для экспорта в .docx потребуется библиотека `docx` (npm)
- Для экспорта в .xlsx потребуется библиотека `exceljs` или `xlsx` (npm)
- Доменная аутентификация — только на этапе 2

## Контакты и контекст заказчика

- **Заказчик:** ОМК-ИТ
- **Система-источник:** СААРЦ (корпоративная система учёта)

- **Инфраструктура этапа 1:** WSL2 Ubuntu на Windows
- **Инфраструктура этапа 2:** Oracle Linux, корпоративный сервер

### [2026-06-20] — Критическое изменение: Отчёт как отдельная сущность

**Контекст:** Заказчик уточнил, что отчёт — это не просто отфильтрованный список данных из источника. Это **отдельная сущность**, которую нужно явно сформировать. СААРЦ не отдаёт готовый отчёт — мы сами его формируем по выбранным параметрам, после чего он сохраняется и становится доступен для редактирования.

**Что изменилось:**

**Было (неправильно):**
- Открыл страницу → применил фильтры → получил список
- Список — это просто отфильтрованные данные
- Нет сохранения, нет истории

**Стало (правильно):**
- Выбрал даты + цех + участок + режим группировки
- Нажал «Сформировать отчёт» → отчёт создаётся и сохраняется
- Отчёт можно открыть позже, редактировать, экспортировать
- Можно сформировать несколько отчётов за разные периоды
- Каждый отчёт — самостоятельный документ с своим ID

**Архитектурные изменения:**

1. **Новая сущность `Report`** (`src/types/index.ts`):
```typescript
interface Report {
  id: string;
  name: string; // редактируемое название
  createdAt: string;
  createdBy: string;
  dateFrom: string;
  dateTo: string;
  shop?: string;
  section?: string;
  groupingMode: GroupingMode;
  downtimes: ConsolidatedDowntime[];
  totalDuration: number;
  totalRecords: number;
  status: 'draft' | 'final';
}
```

2. **Store** (`src/store/AppContext.tsx`):
- Убрал `consolidatedDowntimes` и `loadDowntimes`
- Добавил `reports: Report[]`
- Добавил `createReport(filters, mode, name)` — формирует и сохраняет отчёт
- Все операции с downtimes теперь привязаны к reportId: `updateDowntimeStatus(reportId, downtimeId, status)`

3. **Страницы:**
- `ReportPage` — список отчётов + форма формирования нового
- `ReportViewPage` (новая) — просмотр отчёта с таблицей сводных простоев
- `DowntimeDetailPage` — теперь принимает `reportId` + `downtimeId`

4. **Маршруты:**
- `/` — список отчётов + форма формирования
- `/report/:reportId` — просмотр конкретного отчёта
- `/report/:reportId/downtime/:downtimeId` — детализация простоя

**Ключевые принципы:**
- Отчёт формируется пользователем явно (кнопка «Сформировать»)
- Отчёт сохраняется в localStorage (на этапе 1)
- Отчёт можно редактировать после формирования
- Несколько отчётов могут сосуществовать
- Название отчёта редактируется двойным кликом

**Файлы изменены/созданы:**
- `src/types/index.ts` — добавлен тип Report
- `src/store/AppContext.tsx` — полная переработка
- `src/pages/ReportPage.tsx` — список отчётов + форма
- `src/pages/ReportViewPage.tsx` — НОВЫЙ: просмотр отчёта
- `src/pages/DowntimeDetailPage.tsx` — переработан под reportId+downtimeId
- `src/pages/InvestigationsPage.tsx` — работает через reports

## Известные проблемы и ограничения

- Пока нет бэкенда — на этапе 1 всё работает на клиенте с мок-данными
- SQLite на этапе 1 будет через sql.js (WASM) или better-sqlite3 на сервере
- Для экспорта в .docx потребуется библиотека `docx` (npm)
- Для экспорта в .xlsx потребуется библиотека `exceljs` или `xlsx` (npm)
- Доменная аутентификация — только на этапе 2

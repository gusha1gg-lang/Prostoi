# Портал учёта производственных простоев ОМК-ИТ

## Описание проекта

Веб-портал для автоматизации учёта производственных простоев по вине ОМК-ИТ. Заменяет ручной процесс копирования данных из СААРЦ в Excel, ведения Word-документов с хронологиями и разборами инцидентов, и формирования отчётов для руководства.

## Текущий статус

**Этап 1 (текущий, реализован):** Разработка на тестовом компьютере. Источник данных — вымышленные данные, генерируемые скриптом. Все данные хранятся в localStorage браузера.

**Этап 2 (будущий):** Переезд на корпоративный сервер Oracle Linux. Источник данных — реальная БД СААРЦ через SQL-запросы (без парсинга веб-страниц).

## Ключевая концепция: Отчёт как отдельная сущность

**Важно:** СААРЦ не отдаёт готовый отчёт. Пользователь сам формирует отчёт:

1. Выбирает параметры: даты, цех, участок, режим группировки
2. Нажимает **«Сформировать отчёт»**
3. Отчёт создаётся, сохраняется и получает уникальный ID
4. Отчёт можно открыть, редактировать, экспортировать в любой момент
5. Можно сформировать несколько отчётов за разные периоды

Отчёт — это **снимок данных на момент формирования**. После создания его можно редактировать независимо от изменений в исходной базе данных.

## Функциональные модули

### 1. Формирование отчётов
- Выбор параметров: даты, цех, участок, режим группировки
- Кнопка «Сформировать отчёт» создаёт и сохраняет отчёт
- Отчёт получает уникальный ID и сохраняется в localStorage
- Можно сформировать несколько отчётов за разные периоды

### 2. Список отчётов
- Таблица всех сформированных отчётов
- Название отчёта редактируется двойным кликом
- Кнопки: Открыть / Экспорт в Excel / Удалить
- Информация: период, цех, участок, длительность, количество простоев

### 3. Просмотр отчёта
- Таблица сводных простоев внутри отчёта
- Сортировка по любому столбцу
- Массовые операции: объединение, удаление (для админа)
- Редактирование статуса и названия простоя
- Экспорт всего отчёта в Excel

### 4. Детализация простоя
- 5 вкладок: Детализация, Разбор инцидента, Чат, Файлы, История
- **Детализация:** таблица исходных записей с inline-редактированием
- При редактировании/удалении записи автоматически пересчитывается длительность

### 5. Разбор инцидента
- Структурированный документ с полями:
  - Шапка (номер, уровень, дата, длительность)
  - Таблицы простоев производства и отгрузки
  - Причины (непосредственные, корневые, сопутствующие)
  - Принятые меры
  - Запланированные мероприятия (таблица)
  - Особое мнение
  - Хронология событий (время + событие с датами-разделителями)
- Все поля редактируются администратором
- Экспорт в .docx (Times New Roman, таблицы, жирные заголовки)

### 6. Мероприятия
- Таблица внутри разбора
- Поля: номер, текст, ответственный, срок, формат результата, статус
- CRUD операции (добавление, редактирование, удаление)
- Статусы: выполнено / не выполнено / просрочено

### 7. Хронология событий
- Список записей время + событие
- Даты-разделители (например, «Среда, 19.11.2025»)
- Добавление/удаление записей

### 8. Чат
- Внутрисистемный чат для каждого простоя
- Сообщения с временными метками
- Отображение имени отправителя

### 9. Файлы
- Прикрепление файлов к простою
- Хранение в localStorage (base64)
- Предпросмотр изображений
- Скачивание/удаление

### 10. Уведомления
- Колокольчик в шапке с счётчиком непрочитанных
- Выпадающий список уведомлений
- Автоматическая пометка прочитанными при открытии

### 11. Аудит
- Лог всех значимых действий пользователей
- Фильтры: дата, пользователь, тип действия
- Типы действий: вход/выход, изменение статуса, удаление записи, добавление комментария и т.д.

### 12. Управление доступом
- 3 роли: пользователь, ответственный, администратор
- Администратор видит все простои и может редактировать
- Обычный пользователь — только просмотр
- Профили пользователей с ФИО, должностью, подразделением, email

### 13. Аутентификация
- Вход по логину и паролю
- Тестовые учётные записи:
  - `admin` / `admin123` — Администратор
  - `ivanov` / `ivanov123` — Ответственный
  - `petrov` / `petrov123` — Пользователь
- Пароли хранятся в виде хешей (в реальности — bcrypt)

### 14. Темы
- Светлая и тёмная тема
- Переключатель в шапке
- Сохранение выбора в localStorage

### 15. Экспорт
- **Excel (.xlsx):** отчёт с информацией, сводными простоями и детализацией по листам
- **Word (.docx):** разбор инцидента в формате компании (Times New Roman, таблицы, заголовки)

## Справочник цехов

Цеха приходят из источника в полном формате, например:
- `АО "ВМЗ" - ТЭСЦ-1`
- `ВлФ "МК ОМК-ЭкоМеталл" - Вязники`
- `ООО "ВМЗ-Техно" - КРЦ`

**Для отображения в фильтре** используется короткое название:
- ТЭСЦ-1, ТЭСЦ-2, ТЭСЦ-3, ТЭСЦ-4, ТЭСЦ-5
- МКС-5000
- КПЦ ДЖДК, СПЦ ДЖДК
- ЛПК, ТПЦ
- Спецтехника
- ЦАПТ, ЦЗЛ, ЦПМ
- ВМЗ-Техно КРЦ, ВМЗ-Техно МРЦ
- Эколант ЭМК
- филиалы МК ОМК-ЭкоМеталл

**В базе данных** хранится полное название. Преобразование полное ↔ короткое делается на уровне отображения.

## Служба ДИТ (фиксированная)

Отчёт строится вокруг службы **ДИТ** (Департамент информационных технологий). Эта служба фиксирована:
- Отображается как информационная плашка в шапке
- Не может быть изменена через интерфейс
- Все данные в отчёте относятся только к этой службе

## Группировка данных

При формировании отчёта данные группируются в сводные простои.

**Режимы группировки:**

1. **По цехам за период**
   - Один сводный простой на каждый цех за весь выбранный диапазон
   - Ключ группировки: `цех + название простоя`
   - Разные названия создают разные сводные записи

2. **Все в один простой**
   - Все цеха и дни объединяются в один сводный простой
   - Используется для общего обзора
